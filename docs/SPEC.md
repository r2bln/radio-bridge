# radio-bridge — спецификация (черновик v0)

Удалённый доступ к аналоговой УКВ-станции на даче через браузер: слушать приём и
передавать голос с кнопкой PTT. Минимум железа: станция + дешёвая USB-звуковуха,
передача через VOX.

```
 город (браузер)                      tailnet                 дача, хост taranai
┌──────────────────────┐   wss://taranai:8443/ws   ┌──────────────────────────────┐
│ index.html + app.js  │ ◄──────────────────────► │ radio-bridge (docker)        │
│ PTT, индикаторы      │   μ-law 8 кГц + JSON      │  aiohttp: HTTPS + WebSocket  │
│ mic → TX, RX → колон.│                           │  ALSA ◄─► USB-звуковуха      │
└──────────────────────┘                           └──────────────┬───────────────┘
                                                                  │ TRRS → K-разъём
                                                           Quansheng (VOX)
```

## 1. Железо (дача)

| Что | Решение |
|---|---|
| Станция | Quansheng с K-разъёмом (Kenwood 2-pin), **VOX включён**, частота задана на станции, с компьютера не меняется |
| Звуковуха | USB class-compliant переходник USB → 3,5 мм **LS36** (заказан на Ozon 2026-10-18), одно комбинированное гнездо TRRS. По приезду проверить чип (`lsusb`), частоты и контролы ALSA, стандарт распиновки (CTIA/OMTP) |
| Кабель | Существующий APRS-кабель K-разъём ↔ TRRS 3,5 мм — втыкается в звуковуху напрямую |
| Питание станции | Постоянное (эмулятор АКБ / БП), не от аккумулятора |
| Страховка | **TOT в меню станции** — аппаратный предел передачи независимо от софта |

PTT-линии нет: в эфир станцию выводит только звук на выходе звуковухи (VOX). Отсюда
главное правило: **на выход звуковухи не попадает ничего, кроме осознанной передачи**.

## 2. Компоненты

Один репозиторий, один процесс на сервере, клиент — статическая страница, которую
отдаёт этот же сервер.

- `server/` — Python 3.12+, `aiohttp` (HTTPS, статика, WebSocket), `sounddevice` (PortAudio → ALSA), `numpy`.
- `web/` — `index.html`, `app.js`, AudioWorklet-процессоры захвата и воспроизведения. Без сборщика и фреймворков.
- `Dockerfile` — образ сервера. Хостовая конфигурация и деплой — в репо `infra` (`stacks/radio-bridge`, `hosts/taranai/radio-bridge`), код подключается сабмодулем, как MeteoDumb.

## 3. Аудио

- Формат на проводе: **G.711 μ-law, 8000 Гц, моно, кадр 20 мс = 160 байт** в обе стороны (64 кбит/с). Радиоканал узкополосный (300–3000 Гц), 8 кГц достаточно.
- Сервер открывает устройство через ALSA plug-слой (`plughw:CARD=<имя>,DEV=0`) прямо на 8000 Гц моно — ресемплинг делает ALSA. Устройство задаётся **по имени карты**, не по индексу: индекс USB-карты может меняться.
- Сервер — единственный пользователь звуковухи (на taranai нет PipeWire/Pulse; в контейнер пробрасывается `/dev/snd`).
- μ-law кодек свой (таблицы, numpy / JS) — `audioop` в Python 3.13 удалён.
- В браузере: захват через `getUserMedia` (echoCancellation/noiseSuppression/AGC — выкл, настраиваемо), AudioWorklet ресемплирует 48 кГц → 8 кГц с ФНЧ и кодирует μ-law. Воспроизведение — AudioWorklet с джиттер-буфером (цель 120 мс, настраивается) и ресемплингом 8 → 48 кГц.
- Микшер звуковухи (уровень захвата, выключение AGC) сервер выставляет при старте через `amixer` из конфига.

**Инвариант: в коде сервера нет пути вход → выход.** Принятый звук уходит только в сеть,
выход звуковухи питается только TX-конвейером (§5).

## 4. Приём (RX)

- Вход звуковухи читается непрерывно кадрами по 20 мс.
- **Шумоподавитель-гейт по уровню:** кадр считается «есть сигнал», если RMS выше `RX_GATE_DB` (по умолчанию −45 dBFS, подбирается на месте). Гейт открывается сразу, закрывается через `RX_HANG_MS` (1500 мс) тишины. Пре-ролл `RX_PREROLL_MS` (200 мс): при открытии гейта сначала отправляется буфер последних кадров, чтобы не съесть первый слог.
- Пока гейт закрыт — аудио в сеть не идёт, только статус (экономия LTE).
- Во время передачи и `TX_TAIL_MS` (1500 мс, ≈ задержка VOX станции) после неё RX в сеть не отправляется (станция полудуплексная, отсекаем наводки и хвост).
- Перед отправкой — мягкий ограничитель пиков (хвост шумодава у Quansheng даёт короткие всплески до 0 dBFS) и `RX_GAIN_DB`.
- Клиенту отправляется уровень входа (≈10 раз/с) даже при закрытом гейте — для индикатора и подбора порога.

## 5. Передача (TX)

Конечный автомат на сервере:

```
IDLE ──ptt_down──► WAKE (тон) ──WAKE_MS──► VOICE ──ptt_up──► IDLE
                      │                      │
                      └──── watchdog / TOT ──┴──► LOCKED ──ptt_up──► IDLE
```

- **WAKE:** по `ptt_down` сервер сразу выдаёт на выход тон `VOX_TONE_HZ` (1000 Гц) длительностью `VOX_TONE_MS` (500 мс) с уровнем `VOX_TONE_DBFS`, с плавными фронтами 10 мс. Голос клиента в это время копится в буфере.
- **VOICE:** на выход идёт голос из джиттер-буфера (`TX_JITTER_MS`, 100 мс) с усилением `TX_GAIN_DB`. При опустошении буфера — тишина.
- **ptt_up:** выход — тишина; станция сама отпускает передачу по задержке VOX.
- **Watchdog:** если во время TX от клиента нет аудиокадров дольше `TX_WATCHDOG_MS` (1000 мс) или WebSocket закрылся — немедленно тишина, состояние LOCKED. Обрыв LTE не должен оставлять станцию в эфире.
- **TOT:** через `TX_TOT_S` (**180 с**) непрерывной передачи — тишина, LOCKED, клиенту `tot_expired`. Выход из LOCKED — только через `ptt_up` и новое нажатие.
- Вне VOICE/WAKE на выход идёт **цифровая тишина** (не шум, не дизеринг) — VOX не должен срабатывать сам.
- Клиент начинает слать кадры только при нажатой PTT и перестаёт сразу при отпускании.

## 6. Протокол (WebSocket `/ws`)

Бинарные сообщения — аудио: ровно один кадр μ-law 160 байт.
- клиент → сервер: голос, только при нажатой PTT;
- сервер → клиент: приём, только при открытом гейте.

Текстовые сообщения — JSON с полем `type`:

| Направление | type | Поля | Смысл |
|---|---|---|---|
| C→S | `ptt` | `state: "down" \| "up"` | нажатие / отпускание |
| S→C | `hello` | `version`, `tot_s`, `rate`, `frame_ms` | после подключения |
| S→C | `state` | `tx: "idle"\|"wake"\|"voice"\|"locked"`, `tx_elapsed_s`, `rx_open: bool` | при каждом изменении |
| S→C | `level` | `rx_dbfs`, `tx_dbfs` | ≈10 раз/с |
| S→C | `tot_expired` | — | сработал TOT |
| S→C | `error` | `code`, `message` | ошибки (нет аудиоустройства и т.п.) |

- **Один клиент.** Если уже есть активное подключение — новое закрывается с кодом `4001 busy`. Живость — WebSocket ping/pong (heartbeat 5 с): зависшее подключение освобождается за ≤10 с.
- Версия протокола в `hello`; несовпадение мажорной версии — клиент показывает ошибку.

## 7. Веб-клиент

Одна страница, работает на ноутбуке и телефоне.

- Статус подключения, кнопка «Подключиться» (нужна для разрешения звука в браузере).
- Большая кнопка **PTT — удержание**: мышь, touch, клавиша Пробел. Отпускание / потеря фокуса окна / закрытие вкладки → `ptt up`.
- Индикатор RX (уровень + «гейт открыт»), индикатор TX (уровень микрофона), таймер передачи с обратным отсчётом до TOT, явная плашка LOCKED / TOT.
- Регулятор громкости приёма, выбор устройства микрофона.
- Подсказка при первом входе: принять самоподписанный сертификат.

## 8. Сеть и безопасность доступа

- Сервер слушает **только на tailscale-адресе taranai** (биндинг порта в `override.yaml`: `<ts-ip>:8443:8443`). В интернет не публикуется, авторизации поверх tailnet нет.
- HTTPS с **самоподписанным сертификатом**: при старте, если в `/data` нет `cert.pem`/`key.pem`, сервер генерирует их (CN и SAN — имя хоста и tailscale-IP из конфига). `/data` — volume, сертификат переживает пересоздание контейнера.
- Трафик RX при открытом гейте ≈ 64 кбит/с (+ накладные расходы WebSocket/TLS), TX — столько же.

## 10. Тестирование без выхода в эфир

- Юнит-тесты (pytest): μ-law туда-обратно, гейт RX (пре-ролл, хвост), автомат TX (тон, watchdog, TOT, LOCKED), отказ второму клиенту.
- **Фейковое аудиоустройство** (`AUDIO_DEVICE=fake:<wav>`): RX читается из WAV по кругу, TX пишется в WAV — полный прогон сервер + браузер на одном ноутбуке.
- `TX_DRY_RUN=1` на реальном железе — проверка RX и всего тракта без выхода в эфир.
- **Тестовый хост — любой Linux с гарнитурным TRRS-гнездом** (ноутбук): сервер работает и не на звуковухе. На десктопе с PipeWire все системные звуки по умолчанию идут в разъём → в эфир через VOX. Поэтому два режима устройства: (а) прямой ALSA `hw`/`plughw` с остановленным PipeWire — эксклюзивно; (б) `AUDIO_DEVICE=pulse:<sink>/<source>` — сервер пишет в конкретный sink, при старте предупреждает, если в этот sink играет кто-то ещё. Системные звуки на время теста выключить.
- **Тестовый хост `tvbox`** (tailnet `100.64.0.42`, `ssh tv@tvbox`, Ubuntu 26.04, Sony Vaio, ALC286, гарнитурное TRRS-гнездо) — станция подключена, проверено 2026-10-18:
  - устройство по умолчанию — HDMI (телевизор), системные звуки в эфир не уходят; аналоговый выход `alsa_output.pci-0000_00_1b.0.analog-stereo`, порт `analog-output-headphones`;
  - вход: порт `analog-input-headset-mic` (по умолчанию стоит встроенный микрофон — переключать), громкость **10% = 0 dB** (на 100% WirePlumber ставит Headset Mic Boost +30 dB → фон −35 dBFS, наводка 50 Гц);
  - RX при 10%: фон −75…−90 dBFS, речь −35…−55 dBFS RMS (пики −16…−35), всплески хвоста шумодава до 0 dBFS → нужен ограничитель пиков на RX, на станции включить STE;
  - TX: тон 1000 Гц, −12 dBFS, выход 40% — **VOX срабатывает**, тон слышен на второй станции.
- Первый прогон с реальной станцией — на ноутбуке дома (встроенная карта уже подключена к станции: выход разъёма → передатчик, микрофонный вход ← приём; уровень входа ≈10%, на 100% клиппинг). Эфирные тесты — только с явного согласия, на заведомо свободной частоте / в эквивалент нагрузки.

## 11. Деплой

- Образ собирается из этого репо; в `infra`: сабмодуль `radio-bridge/`, `stacks/radio-bridge/compose.yaml` (`devices: /dev/snd`, `group_add: audio`, volume `/opt/stacks/radio-bridge:/data`, `restart: unless-stopped`), `hosts/taranai/radio-bridge/override.yaml` (биндинг на tailscale-IP, `AUDIO_DEVICE`, пороги). Деплой — пайплайном `infra`, не руками по SSH.

## 12. Этапы

1. **v0.1 — каркас:** сервер + страница + фейковое устройство, весь протокол, тесты. Без железа.
2. **v0.2 — на `tvbox`** (станция уже подключена, режим PipeWire-sink, клиент — браузер с ноутбука/телефона через tailnet): подбор порога гейта, уровня тона и TX, проверка VOX и TOT (dry-run → согласованный эфирный тест).
3. **v0.3 — taranai:** звуковуха, Dockerfile, стек в `infra`, деплой пайплайном, проверка из города через LTE.
4. **Потом (не в v1):** запись принятого, Opus, PWA для телефона, метрики в Prometheus, автоидентификация позывным, аппаратный PTT.

## Не входит в задачу

CAT и смена частоты, декодирование APRS, несколько одновременных клиентов,
доступ из интернета мимо tailnet, покупка другого трансивера.
